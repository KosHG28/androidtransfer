# AndroidTransfer

Прямой перенос данных с любого Android-телефона на любой Android-телефон — по Wi-Fi или по USB-кабелю, без root и без завязки на конкретного производителя (в отличие от Samsung Smart Switch или Oppo Clone Phone, которые работают только в пределах своей экосистемы).

APK собирается автоматически в GitHub Actions при каждом push — см. вкладку **Actions** этого репозитория, артефакт `androidtransfer-debug-apk`.

## Почему не «как Oppo Clone Phone» на 100%

Клон-приложения производителей (Smart Switch, Phone Clone, Xiaomi Mi Move) умеют читать внутренние данные произвольных сторонних приложений (например, файлы Telegram в `/data/data/...`) только потому, что это предустановленные системные приложения **на своей же прошивке** с привилегиями уровня `system/shell`, которых нет ни у одного стороннего APK. Это ограничение песочницы Android, а не недоработка. Кросс-платформенное приложение без root физически не может это обойти.

Вместо этого AndroidTransfer использует все легальные и реально работающие механизмы:

| Категория | Механизм | Требует root? |
|---|---|---|
| Контакты, звонки, календарь | `ContentProvider` (`ContactsContract`, `CallLog`, `CalendarContract`) | Нет |
| SMS | `Telephony.Sms` + временная роль приложения по умолчанию для SMS (`RoleManager`) | Нет |
| Фото/видео | `MediaStore` | Нет |
| Файлы / произвольная папка | Storage Access Framework (`ACTION_OPEN_DOCUMENT_TREE`) | Нет |
| Список приложений | `PackageManager` → массовая установка через Play Store | Нет |
| WhatsApp (медиа + локальный бэкап) | Копирование `Android/media/com.whatsapp/WhatsApp/` — сам WhatsApp хранит бэкап именно там, чтобы его можно было скопировать без root; дальше нужен штатный экран восстановления WhatsApp на новом телефоне | Нет |
| Telegram и другие облачные мессенджеры | Не требуется — история восстанавливается при входе в аккаунт | — |
| Данные произвольного стороннего приложения | **Не реализовано.** Технически возможно только с root или как системное приложение на конкретной прошивке | Да |

## Архитектура

```
core/transport   — P2pTransport: общий интерфейс отправки/приёма поверх двух транспортов
  NearbyTransport     — Wi-Fi/Bluetooth через Google Nearby Connections (P2P_POINT_TO_POINT)
  UsbTetherTransport  — TCP-сокет поверх USB-модема (RNDIS), свой протокол кадров

core/transfer    — протокол и оркестрация
  ProtocolMessage     — сообщения протокола (Hello, Manifest, Records, FileHeader, ...)
  TransferModule      — интерфейс модуля категории (export/importRecords/importFile)
  TransferManager      — ведёт сессию: отправитель проходит по категориям, получатель
                          реагирует на входящие сообщения

modules/*        — по одному модулю на категорию (contacts, calllog, calendar, sms,
                    media, files, apps, appdata/WhatsApp)

ui/*             — экраны на Jetpack Compose + Navigation, ViewModel
```

### Транспорт

- **Wi-Fi** — Google Nearby Connections (`play-services-nearby`), стратегия `P2P_POINT_TO_POINT`: прямое соединение без интернета и без общей точки доступа, с коротким кодом подтверждения на обоих экранах (как в Nearby Share).
- **USB** — обычный кабель между двумя телефонами сам по себе не создаёт канал данных между двумя *телефонами* (в отличие от связки телефон↔ПК). Поэтому на одном из телефонов нужно один раз включить **USB-модем** (Настройки → Сеть → Точка доступа и модем) — это поднимает сетевой интерфейс RNDIS на обоих концах кабеля, и дальше приложение общается по обычному TCP-сокету поверх него. IP-адрес шлюза различается у разных производителей, поэтому в UI есть и подбор типичных адресов, и поле для ручного ввода.

## Что НЕ реализовано в этой версии (осознанно)

- **Root-режим** — по прямому запросу не закладывался.
- **Перенос данных произвольного приложения через ADB (Wireless Debugging)** — технически возможный «максимальный» уровень без root (как это делают dr.fone/MobileTrans: пользователь включает беспроводную отладку, дальше идёт что-то вроде `adb backup`). Требует реализации протокола ADB (включая TLS-парную привязку по спецификации Android 11+) и проверки на реальных устройствах, которых нет в среде сборки этой сессии. Модуль архитектурно обособлен (`modules/advanced`, зарезервировано) и может быть добавлен отдельно, когда его можно будет протестировать на живых телефонах.

## Сборка

```
./gradlew assembleDebug
```

Локально в этой сессии сборка не проверялась «до конца» (нет Android SDK и доступа к `dl.google.com` в этой рабочей среде) — сборка проверяется в CI (GitHub Actions), где интернет и Android SDK доступны в полном объёме. Если CI покажет ошибки компиляции, следующий шаг — их разбор по логам Actions.

## Разрешения

Полный список — в `app/src/main/AndroidManifest.xml`. Ничего не запрашивается заранее «про запас»: разрешение под категорию (контакты, звонки, календарь, SMS, медиа) запрашивается в момент, когда пользователь включает эту категорию в списке переноса.
