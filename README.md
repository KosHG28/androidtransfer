# AndroidTransfer

Прямой перенос данных с любого Android-телефона на любой Android-телефон — по Wi-Fi или по USB-кабелю, без root и без завязки на конкретного производителя (в отличие от Samsung Smart Switch или Oppo Clone Phone, которые работают только в пределах своей экосистемы).

APK собирается автоматически в GitHub Actions при каждом push и публикуется в разделе **Releases** (тег `debug-latest`, обновляется на каждый push) — там же лежит готовый файл для установки.

## Почему не «как Oppo Clone Phone» на 100%

Клон-приложения производителей (Smart Switch, Phone Clone, Xiaomi Mi Move) умеют читать внутренние данные произвольных сторонних приложений (например, файлы Telegram в `/data/data/...`) только потому, что это предустановленные системные приложения **на своей же прошивке** с привилегиями уровня `system/shell`, которых нет ни у одного стороннего APK. Это ограничение песочницы Android, а не недоработка. Кросс-платформенное приложение без root физически не может это обойти.

Вместо этого AndroidTransfer использует все легальные и реально работающие механизмы:

| Категория | Механизм | Требует root? |
|---|---|---|
| Контакты, звонки, календарь | `ContentProvider` (`ContactsContract`, `CallLog`, `CalendarContract`) | Нет |
| Фото/видео | `MediaStore` | Нет |
| Файлы / произвольная папка | Storage Access Framework (`ACTION_OPEN_DOCUMENT_TREE`) | Нет |
| Установленные приложения (сам APK) | Чтение `ApplicationInfo.sourceDir`/`splitSourceDirs` (байты APK не считаются приватными данными в Android, в отличие от `/data/data/...`) → установка через `PackageInstaller` на новом телефоне. Список — фолбэк на случай, если конкретный APK прочитать не удалось | Нет |
| WhatsApp (медиа + локальный бэкап) | Копирование `Android/media/com.whatsapp/WhatsApp/` — сам WhatsApp хранит бэкап именно там, чтобы его можно было скопировать без root; дальше нужен штатный экран восстановления WhatsApp на новом телефоне | Нет |
| Telegram и другие облачные мессенджеры | Не требуется — история восстанавливается при входе в аккаунт | — |
| Обои рабочего стола | `WallpaperManager` — best-effort: чтение работает не на всех версиях Android (см. ниже) | Нет |
| Данные произвольного стороннего приложения (внутри `/data/data/...`) | **Не реализовано.** Технически возможно только с root или как системное приложение на конкретной прошивке | Да |
| Расположение иконок / папок на рабочем столе | **Не реализовано и не может быть реализовано без root.** Это приватная БД конкретного лаунчера (Pixel Launcher/MIUI/One UI/...) — та же песочница, что и с данными стороннего приложения | Да |

## Архитектура

```
core/transport   — P2pTransport: общий интерфейс отправки/приёма поверх двух транспортов
  NearbyTransport     — Wi-Fi/Bluetooth через Google Nearby Connections (P2P_POINT_TO_POINT)
  UsbTetherTransport  — TCP-сокет поверх USB-модема (RNDIS), свой протокол кадров

core/transfer    — протокол и оркестрация
  ProtocolMessage     — сообщения протокола (Hello, Manifest, Records, FileHeader, ...)
  TransferModule      — интерфейс модуля категории (export/importRecords/importFile)
  TransferManager      — ведёт сессию: отправитель проходит по категориям, получатель
                          реагирует на входящие сообщения

modules/*        — по одному модулю на категорию (contacts, calllog, calendar,
                    media, files, apps (включая установку APK через
                    PackageInstaller), appdata/WhatsApp, wallpaper)

ui/*             — экраны на Jetpack Compose + Navigation, ViewModel
```

### Транспорт

- **Wi-Fi** — Google Nearby Connections (`play-services-nearby`), стратегия `P2P_POINT_TO_POINT`: прямое соединение без интернета и без общей точки доступа, с коротким кодом подтверждения на обоих экранах (как в Nearby Share).
- **USB** — обычный кабель между двумя телефонами сам по себе не создаёт канал данных между двумя *телефонами* (в отличие от связки телефон↔ПК). Поэтому на одном из телефонов нужно один раз включить **USB-модем** (Настройки → Сеть → Точка доступа и модем) — это поднимает сетевой интерфейс RNDIS на обоих концах кабеля, и дальше приложение общается по обычному TCP-сокету поверх него. IP-адрес шлюза различается у разных производителей, поэтому в UI есть и подбор типичных адресов, и поле для ручного ввода.

## Что НЕ реализовано в этой версии (осознанно)

- **SMS** — было реализовано (`Telephony.Sms` + временная роль приложения по умолчанию), но убрано: Google Play Protect блокирует установку APK вне Play Store, если он запрашивает `READ_SMS`/`RECEIVE_SMS`/ресивер `SMS_DELIVER` — это стандартная анти-фрод политика против банковских троянов, крадущих SMS с кодами подтверждения, и блокировка не обходится простым согласием пользователя (на многих устройствах кнопки «всё равно установить» просто нет). Для sideload-распространения это несовместимо с самой идеей раздавать APK напрямую.
- **Root-режим** — по прямому запросу не закладывался.
- **«Сделать приложение системным»** — невозможно в принципе без перепрошивки: системный статус даёт не APK, а размещение файла в `/system/priv-app` на этапе сборки прошивки. Это требует разблокированного загрузчика — то есть фактически root-доступа, от которого мы отказались.
- **Перенос данных произвольного приложения через ADB (Wireless Debugging)** — рассмотрены оба реальных способа реализации и оба заблокированы условиями этой рабочей среды:
  1. Написать протокол сопряжения с нуля (SPAKE2 + TLS-хендшейк по спецификации Android 11+) — серьёзная криптография, которую нельзя провалидировать без живого устройства; есть риск получить код, который выглядит рабочим, но не будет корректно договариваться с настоящим `adbd`.
  2. Встроить в приложение настоящий бинарник `adb` от Google, скомпилированный под Android/ARM — официальный `adb` собирается только для ПК, под Android его нужно кросс-компилировать из исходников AOSP через NDK, что тоже нельзя проверить без реального устройства в этой сессии.

  Кроме того, с Android 12 (API 31) `allowBackup=false` стоит по умолчанию, и большинство актуальных приложений (WhatsApp, банки) всё равно откажут `adb backup`, даже при идеальной реализации протокола. Задача реальна, но требует отдельной сессии с физическим доступом к двум телефонам для отладки вживую.

## Сборка

```
./gradlew assembleDebug
```

Локально в этой сессии сборка не проверялась «до конца» (нет Android SDK и доступа к `dl.google.com` в этой рабочей среде) — сборка проверяется в CI (GitHub Actions), где интернет и Android SDK доступны в полном объёме. Если CI покажет ошибки компиляции, следующий шаг — их разбор по логам Actions.

## Разрешения

Полный список — в `app/src/main/AndroidManifest.xml`. Ничего не запрашивается заранее «про запас»: разрешение под категорию (контакты, звонки, календарь, медиа) запрашивается в момент, когда пользователь включает эту категорию в списке переноса. Для установки полученных APK при первом запуске в роли получателя приложение один раз попросит включить «Установка неизвестных приложений» в системных настройках (`REQUEST_INSTALL_PACKAGES`) — это тот же диалог, что и при установке любого APK не из Play Store.
